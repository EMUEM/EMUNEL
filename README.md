# EMUNEL

**EMUNEL** is a multi-protocol proxy platform: deploy, monitor, and manage isolated
proxy instances (EMUNEL Core) from a single web console (EMUNEL Console) — without
ever touching a server.

```
GitHub  →  EMUNEL Console  →  Create Instance  →  Deploy  →  Running  →  Endpoint  →  Manage
```

EMUNEL carries the proven [Lunel](https://github.com/ArasTey/lunel) platform
(console, worker, and relay core) forward under a new name and a fresh accent —
same battle-tested traffic path, rebranded.

---

## What EMUNEL is

| Part | What it is |
|---|---|
| **EMUNEL Core** (`core/`) | The proxy runtime. Relays **VLESS** (WebSocket + xHTTP), **Trojan** (WebSocket + xHTTP) and **Shadowsocks AEAD** over WebSocket, with per-link quotas, expiry and enable/disable. |
| **EMUNEL Console** (`console/`) | The web control plane. Password + GitHub OAuth login, dashboard, 6-step deploy wizard, live logs/connections/metrics, networking & domain management, admin panel — PostgreSQL or zero-config SQLite. |
| **EMUNEL Worker** (`worker/`) | The node agent. Runs Core instances in isolated containers (Docker driver) or rlimit-separated processes (process driver), reports heartbeats/metrics, and reverse-proxies traffic into instances. |

### How configs stay reachable on single-port platforms

Every instance is reached through the Console's public URL under a private
endpoint token:

```
https://<console-host>/i/<endpoint-token>/<core-path>
```

The gateway authenticates by endpoint token, strips the prefix, and proxies HTTP
and WebSocket traffic to the instance's EMUNEL Core through the Worker. This is
why `vless://` links generated by the panel work behind Railway/Render edges
that expose a single HTTPS port — no per-port exposure needed.

## Quick start (fork and go)

Deploy the repository root as **one service** on any platform that gives you
a public HTTPS domain and persistent storage (Railway, Render, …):

1. Fork this repo → add a service from the fork **root** (Dockerfile is
   auto-detected; or start command `python main.py`) → generate a domain → deploy.
2. Open your domain → sign in with the built-in account **admin / admin** →
   **Create Instance** → Deploy.
3. Open the instance → **Config** tab → copy the `vless://` link (or the
   subscription URL) into your client (v2rayNG, NekoBox, Streisand, …).

Zero required variables: embedded SQLite storage and the default admin
account (`admin` / `admin` — change it in **Admin → System** on first login)
are automatic. Optional: attach a PostgreSQL database (auto-detected via
`DATABASE_URL`) and GitHub OAuth (`EMUNEL_GITHUB_CLIENT_ID` / `..._SECRET`).

> Attach a persistent volume at `/data` so instances, links and accounts
> survive redeploys.

Full details in [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md) and
[docs/RAILWAY.md](docs/RAILWAY.md).

### Local development

Requires Python 3.11+.

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python main.py
```

Open **http://127.0.0.1:8080** and sign in with **admin / admin**.

## Repository layout

```
emunel/
├── core/                      # EMUNEL Core (proxy runtime)
│   └── emunel_core/
│       ├── app.py             #   FastAPI assembly: health, transports, management API
│       ├── config.py          #   env + TOML + CLI configuration
│       ├── state.py           #   links, connections, stats, atomic persistence
│       ├── links.py           #   share-link generation (client import URLs)
│       ├── relay/             #   vless / trojan / shadowsocks / xhttp engine
│       └── __main__.py        #   python -m emunel_core
├── console/
│   ├── api/emunel_console/    # Console API (FastAPI + PostgreSQL/SQLite)
│   │   ├── auth/              #   GitHub OAuth + sessions + CSRF + password login
│   │   ├── routers/           #   instances, domains, admin, internal
│   │   ├── services/          #   deployments, gateway, workers, domains, railway
│   │   └── db.py              #   migrations + dual-backend pool
│   └── frontend/              # modular frontend assets (SPA served from panel.py)
├── worker/emunel_worker/      # node agent (drivers, heartbeat, ws-proxy)
├── deploy/
│   ├── docker/                # Dockerfiles + docker-compose stack
│   └── proxy/                 # optional Caddy edge (wildcard TLS)
├── docs/                      # ARCHITECTURE, API, SECURITY, DEPLOYMENT, …
├── tests/                     # protocol + pipeline tests
├── Dockerfile                 # unified single-service image (Railway-ready)
└── main.py                    # one-process entrypoint: Console + Worker + Cores
```
